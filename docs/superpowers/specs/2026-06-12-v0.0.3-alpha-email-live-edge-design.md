# v0.0.3-alpha.email-live (sub-project B) — public-HTTPS edge + build trims — design

**Status:** approved (brainstorm 2026-06-12)
**Builds on:** A (merged, PR #19) — the in-process EmailBridge now fetches inbound bodies from the Resend Receiving API and registers managed DIDs synchronously.

## Context: where B sits

The email-live work is decomposed A → B → C, each its own spec → plan → PR:
- **A (shipped):** Resend Receiving-API inbound body fetch + deterministic registration.
- **B (this doc):** make jig-server able to serve **public HTTPS** so Resend can POST the inbound webhook, plus two banked build-time wins. **Scoped to the smallest path that unblocks C** (config-gated TLS), explicitly deferring full `install.sh`/release-pipeline productionization.
- **C:** live ops/E2E — provision a VPS, DNS A + MX, verify the Resend domain, register the webhook, real email → block → reply → email round-trip.

The canonical server is the **`jig-server` crate in the open-source `jig-protocol/jig` monorepo** (`repos/jig-server/`). A legacy out-of-monorepo jig-server + the closed-source internal servers (jig-enterprise-server/jig-cloud/jig-central) are NOT touched.

## Current state (verified 2026-06-12)

- `JigServer::start()` (`repos/jig-server/src/server.rs:85-92`) serves **plaintext**: `TcpListener::bind(addr)` + `axum::serve(listener, router)`, where `addr = config.bind_address:config.port` from **`ServerConfig`** (the v0.0.1 config). One axum router carries v0.0.1 routes + the merged v0.0.2 router (WSS, `/.well-known/jig`, `/_bridge/email/inbound`). No TLS anywhere.
- reqwest is fragmented: `jig-server` on **0.11** (rustls-tls); `jig-bridge-email`/`jig-pipeline` on 0.12 (rustls, no-default-features); **`jig-nameserver` on 0.12 with default features** (pulls native-tls/openssl). `jig-cli`/`integration-tests` also use it.
- jig-server's `tokio` is `features = ["full"]`; the code uses only `main`/`spawn`/`select`/`net`/`time::{timeout,sleep}`/`sync::mpsc`. The workspace `tokio` is also `["full"]`, and crates that inherit it (jig-pipeline, jig-client, jig-bridge-email) force `full` into the final binary via feature unification.

## B1 — Config-gated static TLS serving

**Goal:** jig-server can serve the existing router over HTTPS, opt-in, without changing the localhost-plaintext dev experience.

- **Config:** add an optional TLS section to `ServerConfig` (where `bind_address`/`port` live). Shape:
  ```toml
  [server.tls]            # absent OR enabled = false → plaintext (unchanged dev default)
  enabled  = true
  cert_path = "/etc/jig/tls/fullchain.pem"
  key_path  = "/etc/jig/tls/privkey.pem"
  ```
  Represent as a `tls: TlsConfig` field on `ServerConfig` with a serde default of disabled, where `TlsConfig { enabled: bool (default false), cert_path: Option<String>, key_path: Option<String> }`. When `enabled = true`, both paths are required — a config-validation error if either is missing.
- **Serving:** in `JigServer::start()`, branch:
  - plaintext (default): today's `axum::serve(TcpListener::bind(addr).await?, router)` — unchanged.
  - TLS: serve the **same `router`** over rustls via the `axum-server` crate —
    `axum_server::bind_rustls(addr, RustlsConfig::from_pem_file(cert_path, key_path).await?).serve(router.into_make_service()).await`.
    `axum-server` (with its `tls-rustls` feature) reuses the `rustls`/`tokio-rustls` already in the dependency tree.
- **Failure mode:** cert/key load or parse failure → a clear `ServerError` at startup (fail fast; never silently fall back to plaintext when TLS was requested).
- Everything (WSS for clients/federation, `/.well-known/jig`, the bridge webhook) rides the single 443 HTTPS listener. Federation peers already connect via WSS-over-rustls (tokio-tungstenite), so an HTTPS origin is consistent.
- **New dependency:** `axum-server = { version = "0.7", features = ["tls-rustls"] }` (compatible with axum 0.7) — added to `[workspace.dependencies]` and inherited by jig-server.

## B2 — tokio feature trim (workspace-wide)

**Goal:** shrink the binary's tokio surface for build-time/size (the `curl|sh`-in-60s KPI).

- **Workspace-wide by necessity:** cargo unifies features across the graph, so the trim must change the **`[workspace.dependencies] tokio`** entry AND jig-server's direct `tokio` dep to the minimal set; trimming only one is ineffective.
- Target feature set (covers all observed usage across the workspace):
  ```toml
  tokio = { version = "1", features = ["rt-multi-thread", "macros", "net", "time", "sync", "signal", "io-util"] }
  ```
- **Verification-driven:** after the change, build + test the **entire workspace**. If any crate fails to compile on a now-absent feature, add back the minimal feature it needs and record it in the spec/plan (don't reach back to `full`). This is the riskiest part of B.

## B3 — reqwest 0.12 dedupe

**Goal:** one reqwest (0.12, rustls) across the tree; drop the openssl/native-tls stack.

- `jig-server`: `0.11` → `0.12`, `{ default-features = false, features = ["json", "rustls-tls"] }`.
- `jig-nameserver`: `0.12` with default features → `{ default-features = false, features = ["json", "rustls-tls"] }` (drops native-tls).
- Audit `jig-cli` + `integration-tests` reqwest entries; align to the same 0.12 + rustls + no-default-features shape.
- Promote `reqwest` to a single `[workspace.dependencies]` entry (`reqwest = { version = "0.12", default-features = false, features = ["json", "rustls-tls"] }`) and have every crate inherit it, so the split can't recur.
- Confirm the result: `cargo tree -d` / cargo-deny show a single reqwest version and no native-tls/openssl pulled by these crates.

## Testing

- **TLS serving (integration):** in `repos/integration-tests`, a test that generates a self-signed cert with `rcgen` (already a dev-dep), writes the cert+key to a tempdir, builds a `ServerConfig` with `[server.tls] enabled` pointing at them on `127.0.0.1:0`, starts the server, and makes an **HTTPS** request (reqwest with the self-signed cert added as a root, or `danger_accept_invalid_certs`) to `/.well-known/jig`, asserting a 200 over TLS. Proves the rustls serving path locally.
- **Config parse:** a unit test that `[server.tls]` parses into the config struct (enabled + paths) and that `enabled = true` with a missing path is a validation error.
- **Trims:** gated by the full workspace `cargo nextest` + `cargo build` + `cargo deny check` passing, plus a `cargo tree -d reqwest` showing one version. No new per-trim tests — the existing suite is the regression gate.

## Deferred (explicitly out of B scope)

- **In-process auto-ACME** (rustls-acme, TLS-ALPN-01) as a second TLS mode — the zero-manual-cert upgrade; layer on when the full turnkey KPI is tackled.
- **`install.sh` productionization** (public 0.0.0.0 bind, domain prompt, wiring the TLS config, DNS expectations).
- **Release pipeline** (CI builds/signs/publishes binaries to `releases.jig.onl`) — load-bearing for the real 60s KPI; effectively its own sub-project.
- These, plus DNS/MX + Resend domain/webhook registration + the real live round-trip, are **C** (or a later turnkey-edge project).
