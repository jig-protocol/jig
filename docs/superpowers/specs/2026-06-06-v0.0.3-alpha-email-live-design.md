# v0.0.3-alpha.email-live (sub-project A) — design

**Status:** approved (brainstorm 2026-06-06)
**Builds on:** the merged in-process `jig-bridge-email` (PRs #17/#18).

## Context: A → B → C decomposition

"Make the email bridge production-ready end-to-end with real Resend" is too large for one
spec. It decomposes into three sequential sub-projects, each its own spec → plan → PR:

- **A (this doc) — email-live code:** the Resend Receiving-API inbound body fetch + the
  provider-trait restructure it forces, and deterministic managed-DID registration.
  Self-contained, MockProvider-tested, outbound send live-verified. **← we are here.**
- **B — public-edge deploy:** jig-server reachable over public HTTPS (TLS termination), plus
  `install.sh` productionization (public bind, DNS, published releases). Unblocks live
  *inbound*. **Banked B-scope items:** trim `jig-server`'s `tokio = features=["full"]` to
  only-what-we-use, and dedupe the reqwest 0.11 (server) / 0.12 (bridge) split — both are
  build-time/size wins for the `curl|sh`-in-60s KPI. (Tokio is left untouched in A.)
- **C — live ops + E2E:** provision a VPS, point DNS A + MX, verify the Resend domain,
  register the webhook, run a real email → block → reply → email round-trip.

This spec is **only A**. B and C are separate.

## Goal

The current `ResendProvider` is unusable against live Resend: `email.received` webhooks are
**metadata-only**, so inbound messages would submit blank blocks (guarded against in #18 by
dropping empty bodies). A closes that by fetching the body from the Receiving API, and fixes
the managed-DID registration race the #18 review flagged.

## Confirmed Resend API contract (verified against live docs, 2026-06-06)

- **Webhook** `email.received`:
  ```json
  { "type": "email.received", "created_at": "...",
    "data": { "email_id": "uuid", "from": "a@x", "to": ["b@jig.onl"],
              "subject": "...", "attachments": [ ... ] } }
  ```
  Metadata only — **no body/headers**.
- **Retrieve received email:** `GET https://api.resend.com/emails/receiving/{email_id}`,
  header `Authorization: Bearer re_...`, optional `?html_format=data_uri|cid`. Response:
  ```json
  { "object": "email", "id": "...", "to": ["..."], "from": "...", "subject": "...",
    "text": "string|null", "html": "...", "headers": {}, "message_id": "...",
    "raw": { "download_url": "...", "expires_at": "..." },
    "attachments": [ { "id": "...", "filename": "...", "content_type": "...", ... } ] }
  ```
- Resend stores the email on receipt, so the fetch is reliable even if the webhook POST was
  missed. Sources: resend.com/docs/api-reference/emails/retrieve-received-email,
  resend.com/docs/webhooks/emails/received.

## A1 — `EmailProvider` trait restructure (metadata + async fetch)

The sync webhook parse can't return a body. Split inbound into a sync metadata parse and an
explicit async fetch. New `InboundNotification` carries the webhook metadata + the id to fetch:

```rust
pub struct InboundNotification {
    pub provider_message_id: String, // = data.email_id (also the dedup key)
    pub from: String,
    pub to: String,                  // first recipient (1:1 restricted-mode)
    pub subject: String,
}

#[async_trait]
pub trait EmailProvider: Send + Sync {
    async fn send(&self, msg: &OutboundEmail) -> Result<ProviderMessageId>;            // unchanged
    fn verify_webhook(&self, headers: &HeaderMap, body: &[u8]) -> Result<()>;          // unchanged (sync)
    fn parse_webhook(&self, headers: &HeaderMap, body: &[u8])
        -> Result<Option<InboundNotification>>;                                        // was -> InboundEmail
    async fn fetch_inbound(&self, n: &InboundNotification) -> Result<InboundEmail>;    // NEW
}
```

`InboundEmail` (full: from/to/subject/body/provider_message_id) is unchanged; it's now the
*output of `fetch_inbound`*, not of `parse_webhook`.

**Rationale (chosen over a single async `parse_webhook` that fetches internally):** the split
keeps verify/parse pure + sync, and lets **dedup run before the network fetch** so provider
redeliveries skip the fetch entirely. The sync metadata is also usable as an early event
trigger before the body lands.

## A2 — Inbound handler flow (rewired around the fetch)

`handle_inbound` order:

```
verify_webhook                       → 401 on failure
parse_webhook → notif                → None: 200 (non-deliverable) · Err: 400
dedup(storage "inbound-seen", notif.provider_message_id) → 200 if seen   (BEFORE fetch)
fetch_inbound(notif) → InboundEmail
        └─ Err: 502, do NOT mark seen → provider retry re-fetches
empty-body guard (fetched body trim-empty) → 200 + loud drop
body.len() > 25 MB                   → 413        (cap now guards the fetched body)
author-as-shadow → managed_dids.register(shadow)   (A3: now synchronous/deterministic)
resolve recipient → ensure 1:1 DM channel + members
build shadow-signed text-render(body) → submit
mark "inbound-seen" with TTL         → 200
SubmitDenied → 429/502/503 as in #18
```

The body now materializes mid-handler. The 25 MB cap + empty guard move to *after* the fetch
(they guard the fetched content). Everything downstream (shadow author, channel, submit,
dedup-mark) is unchanged from #18.

## A3 — Deterministic managed-DID registration (sync fanout)

Replace the fire-and-forget `tokio::spawn` registration race with a synchronous one. No
`jig-bridge-core` API change — `ManagedDidRegistrar::register` stays a sync `Fn(String)`:

- **`jig-pipeline::fanout`:** change `Fanout.bridge_dids` from `tokio::sync::RwLock` to
  `std::sync::RwLock`. `register_bridge_did` / `unregister_bridge_did` become **sync** (`fn`).
  `dispatch_to_bridges` reads the std lock, collects the matching senders into a `Vec`, drops
  the lock, then sends (no lock held across the send loop; no `.await` while locked). The
  enclosing `broadcast_with_members` / `dispatch_to_bridges_public` stay `async`.
- **`jig-server::v0_0_2_bridges::register_and_start`:** the registrar callback drops the
  `tokio::spawn` and calls `fanout.register_bridge_did(did, tx)` synchronously.
- Net effect: `register()` completes the fanout insert before it returns, so by the time
  `handle_inbound` finishes, the sink is live — any reply (a *later* request) is guaranteed to
  find it. The race window is closed deterministically.

**Call-site updates** (all `register_bridge_did(..).await` → `register_bridge_did(..)`): the
B2 fanout unit tests, the B3 ingest dispatch test, the federated-bridge-sink test added in
#18, and `register_and_start`. The integration test's `drain_spawned_tasks()` helper is
**deleted** (no spawn left to drain).

Alternative considered + rejected for higher ripple: making `ManagedDidRegistrar::register`
async (would change the `jig-bridge-core` public API + every registrar test site).

## A4 — `ResendProvider` fetch specifics

- `fetch_inbound(n)`: `GET /emails/receiving/{n.provider_message_id}` (Bearer `api_key`),
  `?html_format=data_uri`. Map the response via a **pure** `parse_received_email_json(bytes)
  -> ParsedInbound` helper (so the mapping is unit-testable without HTTP):
  - **body:** prefer `text` when present + non-blank; else fall back to raw `html`
    (proper HTML→text is a noted later refinement); both empty → empty body (caught by the
    handler's guard).
  - **attachments:** not fetched (no `download_url` call — inline-only deferral). When the
    response lists ≥1, append a single footer line to the body:
    `\n\n[N attachment(s) not delivered]` so the recipient isn't silently short content.
  - assemble `InboundEmail { from: n.from, to: n.to, subject: n.subject, body,
    provider_message_id: n.provider_message_id }`.
- `parse_webhook`: `email.received` (or `inbound.email.received`) → `InboundNotification`
  (`email_id`, `from`, `to[0]`, `subject`); any other type → `Ok(None)`. Missing
  `email_id`/`from`/`to` on a received event → `Err`.
- **Errors:** non-2xx fetch or network failure → `Err` (handler → 502; transient).
- No new `EmailBridgeConfig` fields; `resend_api_key` already covers the fetch auth.
- **`to`:** first element of `data.to` (1:1 restricted-mode; multi-recipient → open-mode later).

`MockProvider` (integration tests) implements `parse_webhook` (canned notification) +
`fetch_inbound` (canned `InboundEmail`).

## Testing

- **Unit (`resend.rs`):** `parse_webhook` (received → notification; non-received → None;
  malformed → Err); `parse_received_email_json` four cases (text present / html-only / both
  empty / with-attachments-footer); Svix `verify_webhook` (unchanged).
- **Handler (`inbound.rs`):** `MockProvider` parse+fetch; cases: happy (block submitted),
  dedup (no second fetch *or* submit), bad-sig 401, non-received 200, **fetch-error 502**
  (new), empty-fetched-body 200-drop, oversized 413.
- **Integration (`integration-tests/tests/h_email_bridge.rs`):** adapt the 5 existing tests to
  the split provider; **remove `drain_spawned_tasks`** (registration is deterministic now).
- **Live outbound smoke:** an env-gated `#[ignore]` test — given `RESEND_API_KEY` (+
  `RESEND_TEST_TO`) it calls `ResendProvider::send` live and asserts a 2xx + message id. Key
  injected via the 1Password / op-secrets flow; never committed. Run manually. Inbound-fetch +
  webhook live verification is **C** (needs DNS / a received email).

## Error handling summary

| Stage | Failure | Result |
| --- | --- | --- |
| verify_webhook | bad/missing sig | 401 |
| parse_webhook | non-deliverable event | 200 (logged, no forward) |
| parse_webhook | malformed | 400 |
| dedup | already-seen id | 200 |
| dedup | storage error | 500 |
| fetch_inbound | non-2xx / network | 502 (not marked seen → retry re-fetches) |
| body | empty after fetch | 200 + loud drop |
| body | > 25 MB | 413 |
| submit | SubmitDenied::RateLimited / PolicyBlocked / Unavailable | 429 / 502 / 503 |
