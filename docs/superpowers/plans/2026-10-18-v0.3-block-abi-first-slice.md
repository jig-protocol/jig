# v0.3 block ABI: first slice

**Date:** 2026-10-18
**Design:** [`2026-10-18-v0.3-block-abi-design.md`](../specs/2026-10-18-v0.3-block-abi-design.md)
(decisions A1–A8) and [JEP-0006](../../../repos/jig-spec/jep/jep-0006-block-abi.md).
**Status:** Plan, not started.

## Goal and exit gate

One component running end to end on server and client, with a cross-architecture determinism
test.

The slice is done when all of the following hold:

1. `text-block`, rebuilt as a `jig:block/renderer@0.1.0` component, is executed by the server's
   `text-render` path, and the server signs a v0.3 `exec` receipt (deterministic CBOR,
   COSE_Sign1).
2. `jig-client` executes the same component for an open channel and compares its outcome hash
   with the server's receipt. A mismatch is surfaced, not resolved silently.
3. Conformance vectors (component, invocation, expected outcome and hash) pass in CI on x86_64
   and aarch64 Linux, both native and Pulley.
4. `text-render`'s `render_hash` is unchanged for the existing test corpus, so servers on mixed
   versions keep agreeing.

Out of scope: bots and `handle`, every `jig:host/*` import, nesting (lane C); `jig block`
tooling and the registry (lane Dv); third-party execution policy beyond an empty default (A7).

## Prerequisites (other lanes)

- **D28: `POST /blocks` removed (L3).** Required before ABI 2 can be deleted (step 9).
- **Engine configuration matches the validator (L2).** wasmtime 49 enables WASM 3.0 features
  and component-model async by default.
- **The receipt's engine version is the exact wasmtime patch (L2).** Step 6 depends on it.
- **L2's dead-scaffolding sweep** (cargo features, capability registries) lands first, so these
  steps don't rebase onto code that is about to disappear.

## Ownership

- `repos/jig-runtime/**` belongs to L2, the `jig-pipeline` executor and ingest paths to the
  server lanes, and `repos/jig-client/**` partly to L7. Each step below names the crates it
  touches.
- The orchestrator assigns each step to a build lane, or to lane A with the owning lane's
  agreement, before it starts.
- Spec page edits (`receipts.md`, `block-execution.md`, `blocks.md`) wait until L1's status

## Steps (one PR each, with its own tests)

### 1. WIT package

- Add `repos/jig-spec/wit/jig-block/` with the package from the design: `types`, `render`,
  `handler` (types only), and the `renderer` and `bot` worlds.
- A test parses it with `wit-parser`.
- New dependencies: `wit-parser`, `wit-component` and `wit-bindgen`, at versions matching
  wasmtime 49's `wasmparser` 0.258. They must pass `cargo-deny`.

### 2. Canonical CBOR for WIT values, and the outcome hash (jig-core)

- A deterministic CBOR encoding (RFC 8949 §4.2.1) of the v0.3 value types: records, variants,
  lists, strings, integers, options and results. No floats.
- `invocation_hash` and the outcome hash are BLAKE3 over that encoding.
- Tests: golden vectors, field-order independence of the input representation, and refusal of
  float types.
- The JEP's type mapping is written from this code.

### 3. Profile validator for components (jig-core)

- `validate_component(bytes, world, granted_interfaces)` implements `jig-det-1`:
  - validate with `(WASM2 | COMPONENT_MODEL) & !SIMD`;
  - walk every core module through `DETERMINISTIC_FEATURES` plus the float ban and the declared
    maxima;
  - check imports against the world and the grants;
  - check exports against the world.
- Tests that it refuses:
  - a `wasi:*` import;
  - a float instruction in a core module;
  - component-model async;
  - a nested component;
  - an export for the wrong world;
  - a memory with no maximum.

### 4. The component path in jig-runtime

- An engine profile that sets features explicitly: `concurrency_support(false)`, NaN
  canonicalization, fuel, and epoch as liveness only.
- `renderer` bindings via `wasmtime::component::bindgen!`. Instances are precompiled once, as
  `CompiledBlock` does today.
- Outcome classification:
  - the export's `ok` and `err` map to `ok` and `error`;
  - deterministic traps map to `error`;
  - fuel, stack and epoch exhaustion and host faults map to `incomplete`.
- Tests:
  - each outcome class;
  - a stack-overflow guest gives `incomplete`;
  - an epoch trap is never reported as fuel exhaustion.

### 5. `text-block` as a renderer component

- Build from `wasm32-unknown-unknown`, wrap with `ComponentEncoder`, and commit the artifact
  beside today's.
- The `wasm-build` CI job rebuilds it and checks byte-for-byte reproducibility.
- Test: for the existing corpus, the component's `render_hash` equals the ABI 1 module's.

### 6. v0.3 receipts and the server switch (jig-core, jig-pipeline)

- A receipt type, a CBOR encoder and a COSE_Sign1 signer and verifier (EdDSA, `kid` = DID).
  New COSE and CBOR dependencies pass `cargo-deny`.
- `text-render` executes the component and emits an `exec` receipt.
- Encrypted channels emit `sealed`, and blocks with no execution emit `accepted`.
- Storage and readers accept both the old JSON formats and v0.3.
- Tests:
  - the signature round-trips;
  - a tampered payload is refused;
  - a `sealed` receipt carries no content-derived field;
  - an old receipt still reads.

### 7. The client executes and compares (jig-client)

- `jig-client` gains `jig-runtime` behind a cargo feature.
- For open channels it executes the component and compares the outcome hash with the server's
  `exec` receipt.
- Divergence on a comparable outcome is reported to the user. `incomplete` is never compared.
- A client built without the feature shows the fallback text and says the block is unverified.
- Tests: agreement, a forged server hash, and an `incomplete` local run.

### 8. Conformance vectors and the cross-architecture matrix (the exit gate)

- Vectors in `repos/jig-spec/vectors/block-abi/`: components, invocations, expected outcomes and
  hashes. They include `text-block` and small purpose-built guests that exercise every value
  type and outcome class.
- A CI job runs them on x86_64 and aarch64 Linux, native and Pulley. It extends the matrix in
  `fuel-portability.yml` or adds a sibling job, and its path filter covers `Cargo.lock` and
  workflow changes.
- macOS runs on dispatch.

### 9. Deletions (no behaviour change)

- **ABI 1, after step 7:** `payload.rs`, the `jig_alloc`/`jig_dealloc` exports and the old
  `text-block` artifact.
- **ABI 2, after D28 and L3's CLI `block` decision:** `Runtime::execute`, the WASI p1 linker,
  `wasi_preview1_deterministic`, the v0.2 `BlockReceipt` and `wasmtime-wasi`. Coordinate with
  L5 on dropping `wasm32-wasip1` from `release.yml` and the toolchain.

### 10. Spec pages (after L1)

- `receipts.md` is rewritten to the v0.3 format and drops fuel-comparison replay.
- `block-execution.md` and `blocks.md` adopt `jig-det-1` and the component worlds.
- Update the threat register rows SC-03, AB-04, OP-07 and PV-02, plus a new
  executor-divergence row.
- JEP-0006 stays Draft until steps 2 and 8 supply its type mapping and vectors.

## Order and parallelism

- 1 → 2 → 3 → 4 run in sequence.
- 5 can start after 1.
- 6 needs 2 and 4.
- 7 needs 6.
- 8 needs 5 and grows with each step; it gates the slice.
- 9 and 10 come last.

Lane C's slices 1–2 can start once step 1 lands.

## Risks

- **COSE and CBOR crates** may not pass the dependency policy. Fallback: a minimal in-tree
  COSE_Sign1 for the single algorithm used, reviewed like crypto code.
- **Stack exhaustion** may differ between native and Pulley in the vectors. That is expected;
  such runs must classify as `incomplete`, never as a divergence.
- **`wit-bindgen` on `wasm32v1-none`** is untested. Step 5 uses `wasm32-unknown-unknown`, which
  is known to work.
