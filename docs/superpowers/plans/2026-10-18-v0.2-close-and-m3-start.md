## Redundancy sweep

Rules:

1. **One implementation of each thing.** Where a v0.0.1 and a v0.0.2 version coexist, keep the
   v0.0.2 one. Delete the other with its config flags, tests and docs.
2. **Code that no production path calls is deleted,** unless a design approved in the current wave
   claims it. Git history keeps it.
3. **Optional backends and features:** either CI builds them, or they go.
4. **Deletions are their own PRs,** with no behaviour change mixed in. Each says what was removed
   and how it was shown to be unused (callers searched, tests still green).
5. **When unsure, list it, don't delete it.** The lane's inventory notes the item and who decides.

## Merge discipline

- **Merge queue.** `main` requires `workspace`, `wasm-build` and `dependency-policy`, and a
  branch must be up to date to merge. With ten lanes, every merge puts every other PR behind.
  GitHub's merge queue removes that churn; turning it on is a repository setting for DJ.
- **Small PRs.** Lanes merge `main` daily. Deletion PRs stay separate from behaviour changes.
- **Drafts skip CI's build jobs.** Validate locally ([`AGENTS.md`](../../../AGENTS.md)), then mark
  the PR ready for review: that runs the full CI, and the queue runs it again on the merged tree.
- **CodeRabbit** never reviews drafts or re-reviews later pushes (`.coderabbit.yaml`). Its free tier
  may also skip automatic reviews here, so when you mark a PR ready, comment `@coderabbitai review`
  once. It reviews about once an hour across the repo, so don't hold merges for it.
- **Builds.** Each session builds in its own checkout and cleans its build output when done
  ([`AGENTS.md`](../../../AGENTS.md)).
- **Commits and PRs.** Branch names follow `type/description`. Commits carry no model
  attribution. PR bodies end with `Human: DJ // Agent: Claude Code`.

## Release (L5)

1. Confirm the signing secret holds the key meant to be jig's long-term release key. The secret's
   public key is labelled `dev@jig.onl`. If it is a development key, rotate it now: once
   `install.sh` ships, rotating means every installer pins a dead key.
2. Run a `workflow_dispatch` dry run on `main`. It signs with a throwaway key, so it tests the
   build, packaging and smoke tests, but not the real key.
3. Add a job that checks the secret against the pins without tagging: approval-gated, in the
   `release` environment, deriving only the public key. Today the real key is first checked when
   a tag is pushed.
4. Make `install.sh` fail closed. When `ssh-keygen` is missing it falls back to a checksum-only
   check, which breaks threat-register SC-02's MUST (verify signature and checksum). Refuse instead,
   with a clear message; the explicit `JIG_VERIFY_SIGNATURE=0` override stays. Weakening SC-02 would
   take an explicit decision from DJ, recorded in the decisions log.
5. Never re-run a failed tag after fixing `main`. Cut a new tag. Tag `v0.2.0-alpha.1` at G1.
