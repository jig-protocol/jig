# v0.3 capabilities, state and nesting: implementation plan

Date: 2026-10-18. Design:
[`specs/2026-10-18-v0.3-capabilities-state-nesting-design.md`](../specs/2026-10-18-v0.3-capabilities-state-nesting-design.md)
(decisions C1–C8). Normative text:
[JEP-0007](../../../repos/jig-spec/jep/jep-0007-capabilities-state-nesting.md).

## Dependencies

- **Lane A's first slice** (WIT package, component path in `jig-runtime`, v0.3 `exec` receipt):
  slices 1–2 below need only the WIT package; 3–8 need A's component path.
- **Lane L2's deletions** of the old capability scaffolding land first. Nothing here reuses it.
- **L7's `ingest` record** for slices 4, 5 and 7; **F's channel ids and `sequencer-set`** for
  slice 9.
- **Lane L1's status sweep** before slice 10 edits spec pages.

Each slice is one PR, with its tests in the same PR. Build with `CARGO_INCREMENTAL=0` and clean
build output when done (`AGENTS.md`).

## Slices

1. **Vocabulary and the algebra** (`jig-core`).
   - `jig_core::grant`: typed scope fields (set, quota, floor) with `⊑` and `⊓`; the five v0.3
     capabilities and their schemas; the dCBOR encoding a program manifest's `requests` and an
     install's `grant` share; refusal of unknown names, incompatible versions and unknown or
     missing fields. (No v0.3 scope needs a flag, so there is none yet.)
   - The manifest change moved: under Dv3 a program's requests live in the program manifest
     (JEP-0011), which uses this module. The v0.2 `BlockManifest.capabilities` stays until ABI 2
     is deleted with it.
   - Tests: property tests that `⊓` is commutative, associative and idempotent and is the greatest
     lower bound; `⊑` agrees with `⊓` and is transitive; no chain of meets exceeds its first
     operand; the empty grant is bottom; encoding round-trips. Unit tests refuse the old
     vocabularies, unknown and missing fields, and non-canonical sets.
2. **Linker per grant** (`jig-runtime`).
   - Build a component linker holding an empty `jig:block/types` instance (types only; lane A's
     wit-bindgen build of text-block, #151 at `c01244e`, imports it) plus only the granted
     interfaces; cache `InstancePre` by (code hash, interface set); import check at upload.
   - Tests: a real wit-bindgen `renderer` that imports only `jig:block/types` links with an empty
     grant; an ungranted import fails instantiation with `capability-refused`; a granted one links;
     a `wasi:clocks` import is refused; no code path defines unknown imports.
3. **Installs and bot DIDs** (`jig-core` kinds, `jig-pipeline`).
   - The `block-install` kind; host countersignature and custodial key; member-add of the bot DID;
     policy check.
   - Tests: a non-owner's install is refused; a grant exceeding the request is refused; an install
     into an encrypted channel is refused; a block outside policy is refused.
4. **`handle` and effects through `ingest`** (`jig-pipeline`).
   - Invoke on triggers; apply `post` through `ingest` with `produced_by`; the apply-time check
     and the `applied` receipt field; hop limit.
   - Tests: a post outside `effects.post.channels` is refused and recorded in `applied` while the
     outcome stays `ok`; a bot is not invoked by its own post; a two-bot loop stops at 4 hops.
5. **State** (`jig-pipeline`).
   - State table keyed by instance; the fold; chained `state_before`/`state_after`; atomic commit
     with effects.
   - Tests: an `error` or `incomplete` run changes nothing; the chain links across runs;
     over-quota state is refused; replaying recorded runs reproduces the final `state_cid`.
6. **fetch-by-CID** (`jig-runtime` host function, `jig-pipeline` store view).
   - Scope check by grant; CID verification; encrypted channels refused; `fetches` in the receipt.
   - Tests: an out-of-scope CID returns `not-granted`; an encrypted-channel block and tampered
     bytes return `not-found`; a re-execution with the recorded answers gives the same outcome.
7. **Timers** (`jig-pipeline`).
   - One pending timer per instance; `timer-fire` blocks authored by the home server; missed
     fires fire once.
   - Tests: set replaces; cancel clears; a fire's `scheduled_at` equals `set_by`'s ingest HLC plus
     `after_ms`; a client flags a fire that contradicts `set_by` or follows a cancel.
8. **Nesting** (`jig-runtime`, `jig-pipeline`). The phase-2 exit tests.
   - Declared children and offers; `compose.invoke`; shared fuel and memory; slot reservation;
     depth limit; `children` receipt tree; separate `host` meters.
   - Tests:
     - a child offered less cannot link what was withheld;
     - a child cannot fetch outside its narrowed scope even when its own manifest asks;
     - effective authority never exceeds the parent's at any depth (property test over random
       trees);
     - a child's fuel and memory come out of the root's; a child's fetches count against the
       root's quota;
     - exhaustion anywhere makes the root `incomplete`; a child's `block-error` reaches the parent
       as `failed`;
     - depth 5 and an undeclared child are refused;
     - the same tree gives the same outcome and receipt (minus telemetry) on two hosts, x86_64 and
       aarch64.
9. **Sequencer moves** (`jig-pipeline`, after F's `sequencer-set`).
   - Reinstall from `sequencer-set`; state by CID with replay fallback; timer re-derivation;
     fork-side writes not applied.
   - Tests: state survives a move; a pending timer fires once on the new sequencer at its original
     `scheduled_at`; writes past the handover head are dropped.
10. **Spec and threat register** (after L1).
    - `block-execution.md` capability section rewritten to JEP-0007; `receipts.md` fields with lane
      A; threat-register rows AB-04, OP-07, SC-03, AB-07 and SC-04.

## Exit

Phase 2's second criterion is met when slice 8's tests pass in CI on both architectures and the
threat-register rows from slice 10 have merged.
